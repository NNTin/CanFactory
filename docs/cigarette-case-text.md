# Cigarette case: text on the underside

Four parameters put a line of text on the underside of the large box (the face that sits on the print bed):

| Key | Kind | Default | Meaning | SCAD variable |
|---|---|---|---|---|
| `engraveText` | text, at most 20 printable ASCII characters | empty (no text) | The text. Empty or only spaces means none. | `TEXT` |
| `textFont` | enum: `sans`, `serif`, `mono`, `wide` | `sans` | The font (all bold, see `models/fonts/README.md`). | `TEXT_FONT` |
| `textSize` | 3 to 10 mm, step 0.5 | 6 | Letter height (OpenSCAD's `text` size, about a capital's height). | `TEXT_SIZE` |
| `textMode` | enum: `engrave`, `second-filament` | `engrave` | See below. Not passed to SCAD: it decides which parts are rendered. | none |

## The two styles

- `engrave`: the letters are carved 0.8 mm into the underside of `case-box` (the floor above it is 2.45 mm thick). Any printer.
- `second-filament`: the box is carved exactly the same way, and a sixth part, `case-text`, is added to the ZIP. It is the
  same letters (0.8 mm thick), in the box's own coordinate frame with the underside on z = 0, so importing it into the slicer
  together with `case-box` puts it in the carving, flush. Print it in another colour on a multi-nozzle printer, or with a
  filament change. It exists only when the mode is `second-filament` and the text has a visible character
  (`ModelPart.includedWhen`, `activeParts()` in `packages/contracts`); its letters are separate bodies by design
  (`ModelPart.separateBodies`, so the mesh check allows several closed bodies for it, and only for it).

## Layout

The text is one line, centred on the free, flat underside: `x` from -9 to 26 mm (clear of the round bay and the flange edge)
and `y` within 8 mm of the centre line. It is mirrored, so it reads correctly when the box is turned over. `SCAD` clips the
letters to that area, so nothing can reach the bay or the edge; the contract makes sure that clipping never happens:

- `textWidth()` adds up the measured advance width of each character (`packages/contracts/src/textMetrics.ts`, generated by
  `tools/generate-text-metrics.ts` from the fonts in `models/fonts` with OpenSCAD's own `text()`), and `validateParameters`
  rejects text wider than 34.5 mm ("shorten it or lower the text size"). At size 6 that is about 10 characters of "Hello"
  width; at 3 mm about 20. Kerning is ignored, which is why the limit is 0.5 mm inside the area.
- The tallest text (10 mm size, with descenders) is 14.4 mm high, inside the 16 mm area.

## Fonts and reproducibility

`text()` needs fonts, and the renderer would otherwise use whatever the host has (the wasm build has none). The four fonts are
therefore bundled in `models/fonts` and OpenSCAD is pointed at them: `OPENSCAD_FONT_PATH` in the worker
(`apps/worker/src/render.ts`), in the test harness Docker runner and in `tools/stl-to-scad/openscad.ts` (which also
installs them into the wasm runner). The fonts are part of the model's cache fingerprint (`ModelDefinition.assetPaths`).
If a font is missing, `text()` renders nothing: for the box that would mean no engraving without an error, so keep the fonts
folder in the worker image (it is under `/app`, which the Dockerfile copies).

## Safety of the text value

The worker passes it as `-D TEXT="..."` with `JSON.stringify`, which escapes quotes and backslashes the way OpenSCAD strings
expect, through `execFile` (no shell). The schema also limits it to printable ASCII, so no control characters or non-ASCII
reach the renderer.

## Keeping the two SCAD files in sync

The block between `// --- underside text` and `// --- end underside text ---` is identical in
`models/cigarette-case/reference/11_v11.3__-_honeycomb_-_box.scad` and `models/cigarette-case/underside-text.scad`; a test in
`packages/contracts/src/models.test.ts` fails if they differ, because the text part must fill the carving exactly.
